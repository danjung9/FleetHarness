# FleetHarness Studio direction

Scope: a separate alternate UI at studio/index.html. The original app, original styles, backend implementation, skills, catalog, and project storage remain intact. Mode: Operate. The user's named Startups.RIP reference pins the visual direction; the concept seed was run and acknowledged, but its assignment cannot override that reference. Code-led implementation using the actual reference, no generated bitmap assets or comp approval required.

Visual world: charcoal and warm ivory, orange actions, large editorial serif display paired with self-hosted DM Sans, quiet thin rules, readable directory cards. The catalog is content, not simulated applications. A browser opens on a searchable directory of the existing 34 Norfolk entries. Detailed briefs expose six explicit sections and the real recipe's skills and tools. The live Norfolk page currently requires sign-in; source summaries are the repository's captured catalog, not a fresh scrape or official evaluation rubric.

First viewport: a compact horizontal navigation; a generous, centered two-line editorial headline; a direct new-brief action; a search field and category filters; then three readable challenge cards. The first three entries are actual pilot challenges. No invented performance statistics or generated software screenshots.

Signature interaction: a challenge entry becomes an editable six-section brief, then a live build workspace. Warm orange links discovery, editing, and execution. Cards respond with a restrained border change; motion is a short, already-visible page reveal and disables under reduced motion.

State: browser drafts and desktop Studio state are independent of the incumbent. Browser generation is explicitly unavailable; desktop uses the same window.fleetHarness bridge, Pi sessions, selected domain skills, tools, verification, human review and export. All output states derive from the backend. Suggested deliverables and evaluation criteria are identified as FleetHarness suggestions.

Responsive: three-column directory becomes two then one; horizontal categories wrap; detail/editor/build sidebars become in-flow below content; no clipped headings or horizontal page scroll. Text and controls maintain contrast and visible keyboard focus.
