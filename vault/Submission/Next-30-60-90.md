# AppYard: next 30, 60 and 90 days

[R] Move from synthetic proof to a useful, supportable task app. This is a proposed path, not a fielding authorization or owner commitment. [P] Rule 11 calls for owners, an experiment, resources and transition recommendations. [Event rules](../Event/Rules.md).

| Responsibility | Person-owned blank [R] |
| --- | --- |
| Mission owner | **[MUKUL TO SUPPLY: training-workflow sponsor and acceptance authority].** Confirm the task and useful outcome. |
| Technical owner | **[MUKUL TO SUPPLY: maintainer and release/support owner].** Own fixes, dependencies, monitoring, updates, rollback and shutdown. |
| Security and data review | **[MUKUL TO SUPPLY: responsible role and review route].** Approve target devices, data and integrations. |
| Resources | **[MUKUL TO SUPPLY: availability, hours and budget].** Permitted device/browser, willing user, independent reviewer, maintainer and security/support advice. Generation needs authorized model access. |

[R] **Next experiment:** independently judge saved ten-challenge outputs, then select one accepted artifact for a matched synthetic user trial. Record its revision/digest, baseline and app times, correctness, assistance and review effort. If no artifact is accepted, repair the factory and repeat the original requirements. Do not hand-edit a generated app to claim autonomous success. [Benchmark](../Research/QA/Ten/Scoreboard.md), [trial protocol](../Research/QA/Officer/Trial-Protocol.md).

| Gate | Evidence needed to continue [R] |
| --- | --- |
| 30 days | Confirm user, process and owners. Resolve actual task defects, review binding and guide accuracy. Reconcile clock/readable-export expectations with the agreed brief before requiring changes. Measure total task and review effort; retain failures. |
| 60 days | With owner approval, test the delivered artifact on the intended device: offline cold launch, interrupted recovery, installation, update and rollback. Verify sources and durable action history. Prove connector registration and permitted access separately. If sync is required, test two-device conflict, interruption, retry and convergence. |
| 90 days | Decide transition, further work or stop using measured benefit, defects and support cost. Require distribution authority, license inventory, vulnerability response and support owners. Assess repeatability across already attempted challenge domains using independent satisfactory outcomes. |

[E] Historical offline save/import covers one partial training HTML app. It does not certify current CLI/service delivery, government-device operation, sync or offline generation. [Candidate review](../Research/QA/Acceptance/Review-Candidates.md). [R] Include cybersecurity, storage protection, shipboard connectivity, portability and sustainment in the device review; packaging needs its own receipt.

[R] The mission owner approves scope and acceptance; the technical owner monitors failures, usage and versions. Allow only synthetic/public data and approved prototype work. Stop progression on failed acceptance or shutdown, escalate to Mukul and the owners, and verify worker termination before resuming. This plan authorizes no real-account access, deployment or publication.
