## Root causes

### 1. Commit identity creates a review cycle the worker cannot resolve

[E] org.py sets IDENTITY to divinedev111, configures clones with it and commits centrally. The event instructions require Mukul. Its test_org.py even asserts the conflicting identity. Both d591223 and d402b67 were returned solely for author correction.

[E] The charter prohibits workers from committing or changing history. dev-1 responded with metadata evidence and another focused test run, but could not perform the requested correction. handle_review sends all change requests back to the implementation seat. When a return changes no tracked files, handle_code releases the claim and exits without creating a replacement commit or resubmitting review.

[R] Fix identity at the committing coordinator, correct only the affected unlanded metadata while preserving trees, and re-review the replacement commit. Route administrative failures to the coordinator, not to an implementation worker that lacks the required authority. The review itself was following the stated rule.

### 2. Old assignments survive newer decisions

[E] enqueue appends with no deduplication or replacement. The 15:34 snapshot had two dev-1 entries. After the newer authorized implementation and author-review response, a retained older assignment ran at 15:54:55. Its journal records stale disabled wording, narrower scope and a renewed 16:00 cutoff. It produced a prerequisite reconciliation instead of advancing the completed fix.

[E] The queue also contained an agentic-builder assignment with dependencies in prose but no files or done_when metadata. Current director ingestion requires those fields, but dispatch does not validate older or other queue entries. An isolated probe confirms a task with absent file metadata dispatches despite another seat holding the named file; adding the metadata correctly blocks it. This is a dispatch weakness, not evidence of concurrent writes to the same physical checkout.

[E] dev-2 additionally changed pi-backend.ts outside its recorded file claims while agentic-builder owned that logical file in another clone. The reviewer accepted the explained scope exception, but the scheduler's single-writer claim did not cover it.

[R] Version tasks, explicitly supersede earlier allocations, validate metadata at dispatch and update file claims before approving scope exceptions. Dependencies should reference completed task IDs or landed revisions, not prose alone.

### 3. Environment failures are returned as implementation failures

[E] The runner gate executes inside a sandbox. dev-3's change requires launching a native verification sandbox. Its eight native failures report sandbox_apply: Operation not permitted before generated tests execute. Worker starts at 15:53:01 and 15:56:30 are gate-failed retries of this same constraint. Improved error text does not prove native execution or remove the enclosing restriction.

[E] The baseline itself produced 147 passes and 20 failures inside the sandbox. The outside-sandbox automatic receipt for d0f4c69 reports 116 unit and 51 harness passes. Five GUI smoke scripts fail separately on stale fixture/selector/layout expectations. The early 96-pass count also omitted the later harness total. These contexts must not be merged into a product-regression claim.

[R] Keep isolated unit checks in the worker environment. Send native containment/browser checks to the existing authorized runtime owner, preserve the inner containment boundary and hold delivery on those receipts. An unchanged host restriction should consume no repeated implementation retries. Known-failure allowances should remain explicit baseline comparisons, not be called full acceptance.

### 4. Reporting is expensive and does not measure completion

[E, 48 completed records sampled about 15:56] Status accounting totals 5,327,507 uncached input/output tokens and 55,017,348 input/output tokens including cached input. parse_usage explicitly computes these two values. [E] A status ok value means a nonempty model reply, exit zero and no turn timeout. It does not mean a fix landed, tests passed or a blocker was resolved. Several successful turns are explicit blocked reports. Director memos track their own word counts and checks while delivery remains open.

[R] Stop repeated status-only assignments unless evidence changes. Keep one coordinator, implementation owners and an independent checker for the current critical path. Track submitted candidate, tested revision, review verdict, landed revision and accepted artifact as separate milestones. Add accurate current-run telemetry and cost accounting before interpreting the budget cap as cost control.
