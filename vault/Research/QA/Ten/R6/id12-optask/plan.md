## Failure, recovery and oversight

Empty/invalid source never disappears: show issue and preserve draft; valid unrelated records remain visible but review/export is blocked until source issues are corrected. All fields can be corrected through the original raw draft and reparsed; never patch extracted timestamps silently. Editing, changing selection or loading a sample invalidates derived result/review; show stale state until reparse. Prevent duplicate parse/review clicks during loading. Source issue acknowledgement alone cannot clear quarantine. Unsaved drafts survive normal interactions; deliberate save/discard required before review. Clear requires confirmation. Storage quota/denial and offline-cache failures show actionable messages and preserve working text; user can retry or copy source. Render source via text nodes, not executable HTML.

Monitor local parse/cache/storage errors and counts in the interface; diagnostic logs must omit source contents and secrets. Unknown or contradictory content escalates to user source review; no automated operational decision. Stop local prototype by closing browser/stopping server through host controls; resetting local draft/cache is deliberate and app-scoped. No live-system escalation or shutdown integration is simulated as real. Human review must assess usefulness, readability, synthetic format fidelity and source meaning; real-system connection, real-format accuracy, authority to operate and operational approval remain unestablished. Verification records operational prohibitions and approval gate, not a claim that tests grant them.

## Verification thresholds and risks

Required capabilities: extraction/evidence, normalization/selection and review/export. Host exact evaluators require score 1 across complete JSON responses, one deterministic trial each; 15 new input cases span all three capability groups. Empty-output baseline has event recall 0 on positive cases and cannot pass exact envelopes, recorded baseline score 0. Application event precision/recall must both be 1 on all prepared fixtures including non-events; source evidence equality and UTC/clipping correctness must be 100%. Numeric tolerances are unnecessary at minute precision. Review/export state needs browser evidence in addition to process-isolated core tests.

Risks: invented grammar is no substitute for actual USMTF; browser storage and service-worker support need live checks; a route exercise cannot establish true disconnected use; line-ending normalization can invalidate spans; unsaved state can cause review of wrong content; overlapping bars can obscure short windows; dense messages may reveal performance issues. Use the frozen literal expectations, not observed output, to repair. The independent judge must inspect complete transformation, all named outputs, requested mock input-format fidelity, truthful disclosures and the actual real-data dependency. No successful structural or browser check alone proves semantic adequacy or operational readiness.
