## Data contracts and invariant boundaries

The public invocation in solution-contract.json is complete and authoritative for pure parse/workflow/reconcile actions. Every route calculation used by the UI and application tests calls compute.mjs/casrep.mjs. No second frontend workflow engine. The pack's reconciliation primitive handles immutable DAG/head validation; application code adds canonical-field comparisons, role checks, explicit resolution and approval validity. Never equate a single reconciled head with approved content.

Use the exact fixture report, revision, route and event schemas from data/README.md. Successful event records are derived server-side from command inputs and computed transitions; ignore caller-supplied prior/new status or approval flags. Add revision SHA-256 digest to separately stored decision metadata so each approving actor, decision, timestamp and exact content digest can be reviewed, without altering the fixture's exact export shape. The actor selector is explicitly simulated and the service enforces its synthetic permissions; a user-selected actor is not authentication.

Persist the workspace as an atomic JSON snapshot/journal through store.mjs using built-in filesystem APIs. Mutable data lives outside the runtime allowlist (local application data directory with documented startup path), never in fixtures or deployed source. Serialize updates and compare base revision to reject concurrent stale saves. Save before showing Saved. A storage failure leaves the previous durable file and success audit unchanged. Rejected attempts have a separate persisted log: monotonic attemptId, actorId, action, revisionId, reason, server timestamp. Keep blocked work visible; escalation is an in-app notice to the current holder/owner only. Invalid history/cycles/ID collisions fail closed and preserve original queue, requesting missing history. No simulated reconnect or byte upload subsystem is needed: this scope has a local service, not disconnected multi-device transport.

Browser dirty buffers persist locally and are distinct from committed server state. Role/sample/report switches while dirty offer deliberate Save/Discard; approval or export cannot silently act on different committed content. Export failure preserves dirty text and durable state. Draft exports are clearly draft; released exports are immutable and reproduce exact supplied text for the principal scenario. Export is never official release.

Fixture demonstration mode uses supplied timestamps, IDs and action text defaults in sequence: EV-001-01..12, REV-001-A/B, and their exact event text, route/rule versions. Each individual human action must still pass the same domain guards. A user-entered decision overrides a default. The clock/ID preset is labeled synthetic scenario time and never skips reviews or supplies answers. Ordinary new reports use unique generated IDs and actual UTC timestamps with the same schemas. All exact principal export comparisons use the independently fixed fixture metadata and JSON insertion order/two-space indentation/unescaped Unicode/terminal LF. No one-click full-route replay in the UI.

Linked UPDATE/CORRECT/CASCOR are new report records, not revisions of released content. Validate predecessor is released, same family/equipment/JSN, new report ID, no inherited reviews; demonstrate sequential release in integration tests. CASCOR closes the family only when released. Model linked supersession, cancellation and expiry as explicitly synthetic lifecycle notices with actor/reason/time and audit, never deletion of released content. Require explicit cancellation/expiry action; do not invent operational deadlines or treat cancellation as a Navy transmission. Read-only history retains all relationships.

## Failure, human control and operational review

Parsing, wrong role, missing approval, conflict, stale content or storage failure stop progression and identify the correction/holder. Only explicit human interaction approves and mock-releases; no autonomous publication. Keep local monitoring separate from successful decisions. Shut down via host Stop; preserve inherited process environment for descendants. Restart restores durable state without executing or replaying release. Do not connect identity providers, Microsoft 365, classified systems or Navy message channels. Prohibited marking placeholder is a synthetic rejection test, not real classified data.

Fielding requires independent review of NWP 1-03.1 and OPNAVINST 4790.4 mapping, all synthetic routing assumptions, authenticated roles/delegation, encryption/key and device design, retention, concurrency, release channel and acknowledgement semantics, classification boundaries and operational authority. Plain files/localStorage are not encrypted or operationally secured. No performance/readiness benefit has been measured. Keep source requirements verbatim and these limitations upfront in verification.md, README/user guide and review summary. Human owner must approve the concrete revision before delivery/deployment. Synthetic case correctness does not satisfy real-format validation or operational readiness.
