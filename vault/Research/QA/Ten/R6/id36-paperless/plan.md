# Implementation plan

Audience and outcome: expeditionary tablet capture and command staff review of the complete synthetic UC36 packet. Architecture is published in system-design.json. No application code is produced in this phase. All 43 criteria retain source meaning; 13 operational outcomes remain deferred. Owner approval is required before delivery/deployment.

## Runtime, reuse and actual offline boundary

Select node-service 1.0.0 with offline pack. Host copies every catalog runtime file plus foundation-lock.json and pack files after planning. Read FOUNDATION.md and inspect copied compute/lib functions before adapting. Node 22.19+; no npm dependencies beyond platform, no model environment variables or remote inference. No optional Impeccable engine was run; direct Shape/Operate guidance informed task hierarchy and recovery.

The supported topology is one local device running the service on loopback, with browser IndexedDB and embedded inputs. Disconnect external connectivity while keeping the device-local service available. This demonstrates offline operation without a cloud backend; it does not demonstrate a remote-browser-only deployment. HTTP health must remain available locally. A stopped local service is explicit computation unavailability: retain drafts and offer retry; never report an extraction success. Government managed-device compatibility is deferred. Shared backend handles every domain decision; browser only rasterizes/captures, renders, persists transactions and calls the API. No separate browser rules engine. Test actual offline reload with external request blocking/network disconnected outside loopback; a UI toggle alone is not evidence. Record this manual/environment test in verification.md alongside host journeys.
