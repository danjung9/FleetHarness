# Frozen synthetic language and time contract

The invented data format is a versioned JSON object, not a naval interchange format. Root fields: `schemaVersion:1`, `classification:'synthetic'`, `disclosure`, `epoch:'2026-11-02T00:00:00Z'`, `horizon:{start:0,end:10080}`, `policy`, `people`, `resources`, `operationalWindows`, `templates`, `recurrence`, `priorDuty`, `maxNodes`, `revision`. All times are integer minutes relative to epoch, UTC; half-open intervals [start,end). UI shows Mon to Sun and HH:mm in UTC with dated week heading. No local timezone conversion or daylight-saving inference.

People: ID/name, qualification strings, availability intervals, `minRestMinutes`, `maxMinutes`. Prior duty contains person/start/end/duration, counts toward the explicitly declared demonstration horizon budget even if before epoch, and participates in pairwise rest. Resources are registered exclusive capacity-one IDs with available intervals. Operational windows and per-template permitted windows must contain the whole drill. Unknown IDs, duplicate IDs, negative/zero durations, malformed/reversed windows, missing policies, unqualified assigned people and incomplete occurrence inventories must never create a reviewable result. Prior duty is explicitly permitted before epoch; future requests must lie inside the horizon. Adjacency is non-overlap, but rest remains an additional constraint.

Template: `id`, `department`, `agent`, `title`, `durationMinutes`, `requiredQualifications` (one distinct person per role in this fixture), `roleCount`, resource requirements and ordered alternatives. Alternative: ID, exact people IDs, resource IDs, integer start and rationale. Choose exactly one alternative per occurrence; no duplicate request can masquerade as a mutually exclusive personnel choice. Board pinning records a selected legal alternative; validation checks the whole board including collisions. Optimize can negotiate among saved allowed alternatives again and shows any changes; validation does not move pinned assignments silently.

Policy `SYN-PB4T-1` is explicitly invented: minimum rest 60 minutes; budgets apply over all supplied current and prior duty, not rolling daily fatigue limits. No rule claims to encode SFTRM. All six occurrences are mandatory. A template change to Engineering duration applies to both Engineering occurrences, invalidates old results and retains due windows. Default maxNodes=5000, integer 1 to 200000; increment each attempted partial allocation and stop before exceeding the cap. A one-node six-request run cannot find a complete assignment; it is unknown, never infeasible.

Recurrence format: stable rule ID, template ID, anchored due timestamps (or integer interval with anchor), last-completion history, occurrence release/due windows, horizon carry-out. Expand obligations whose due timestamps lie in the horizon, retain history and next due outside it. Early completion satisfies its specific obligation without resetting the anchor. Do not accept an empty request set as a completed training week.
