## Concrete risks and handoff questions

| Acceptance / concern | Finding, consequence and unresolved choice for planning |
| --- | --- |
| UC12-1; DELIVERABLE12-1 | Generic EVENT/TASK parsing is insufficient. The synthetic grammar and reviewed mapping must explicitly express frequency plans with invented values/units, crypto change-over windows with fictitious labels, and flight quarters intervals. The supplied sources contain no validated real-format mapping. Which documented invented syntax and dense sample will demonstrate all categories? This is a routine synthetic design choice, not a reason to defer. |
| MSG-01 | Trimming input, converting CRLF, splitting on delimiters or using byte/code-point offsets can break provenance. Keep raw text intact; every emitted field needs verifiable UTF-16 spans, including non-ASCII and later lines. What representation preserves both extracted and reviewer-corrected values without overwriting evidence? |
| MSG-02 | Empty input, invalid calendar dates, missing zones, unsupported lines, missing fields and duplicates need visible reasons and recovery. Valid mixed-input records must remain inspectable; unresolved items must not silently enter a confirmed schedule. Is correction performed against a preserved source revision or a separate reviewed value? Reparse must not accumulate events. |
| MSG-03 | Normalization alone supplies no daily rendering. Day clipping could lose cross-midnight duration or change instants. S3 uses a UTC day as an explicit synthetic display assumption; full intervals and continuation need to remain discoverable. Equivalent offset timestamps and invalid/reversed intervals need independent expected outcomes. |
| MSG-04 | No independent answer key or accuracy measurements supplied. Toolkit fixtures cannot establish application accuracy. A separately authored held-out synthetic set must include intentional non-events and category-specific fields, with event counts and field/time discrepancies. Expert validation remains distinct from synthetic key review. |
| MSG-05 | No application or offline browser evidence exists. Local parsing is only part of the workflow: source inspection, review, timeline and export also need offline behavior. Asset delivery, reload/persistence, export format and disconnected-browser verification remain unresolved. A network-dependent CDN or model would threaten this criterion. |
| Export and usability | S3 requires readable offline reviewed output, status, provenance and unresolved-item disclosure. Which format preserves those fields, full timestamps and cross-midnight boundaries? No accessible timeline, keyboard workflow or narrow-screen behavior has been evaluated. |
| Future real-format assessment | Actual USMTF revision, authorized representative variants, reviewed field mapping and operational time conventions are unknown. Future domain review and authorized data would be needed to assess real-format suitability; none were obtained. Synthetic examples must never imply real frequencies, crypto material or operational scheduling rules. |

The required disclosure is “Synthetic, not validated against the real format.” It belongs in later UI, samples, exports and evidence. Research leaves all seven acceptance IDs unverified and unchanged, with no primary deferral proposed. Lack of an official mapping does not excuse a generic substitute for the complete named synthetic workflow.
