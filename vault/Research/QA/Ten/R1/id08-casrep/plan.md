## Data contract and authority

- Store envelope: schemaVersion 1, monotonically increasing generation, reports, revision DAG, immutable audit events, working draft and selected record. One report is sufficient; internal IDs unique across saves, human revision numbers per report. Fresh browser contexts start empty with Originator selected. Revision numbering: base 1, competing amendments 2 and 3, explicit resolution 4.
- Report: id, type INITIAL, equipment, casualty description, optional demonstration category text, current revision ID, heads, workflow status, holder, current approvals, lifecycle relationships. Equipment and casualty are trimmed, required and limited to 200 and 2000 characters respectively. Category is explicitly a demonstration label, not an invented NWP category set. The export states SYNTHETIC, NOT AN OFFICIAL MESSAGE.
- Revision: immutable {id, recordId, parents, actor, value}; value is a canonical serialized snapshot string, null a technical tombstone. Record display number separately; do not infer ancestry from display numbers or clocks. Validate unique IDs/content, same-record existing parents, acyclicity, and deterministic union. Exact immutable content identity plus canonical snapshot digest binds approvals; choose deterministic digest available offline without claiming cryptographic certification.
- Decision/audit: unique event ID, report ID, revision ID, snapshot digest, actor persona, role, action, comment, timestamp. Store prior invalidated approvals for history but exclude them from current authority. Synthetic actor names are not authentication. Returned comments remain readable after resubmission/export. Audit includes resolution actor, both heads and chosen content.
- Draft buffer is separate from committed content. Persist it for reload recovery; mark Unsaved changes relative to the current committed snapshot. Ordinary persona/panel changes preserve it. Save or explicit Discard is required before review actions. Errors do not replace the committed state.
- Lifecycle records reserve amendmentOf, supersedes, cancelledBy, expiresAt and lifecycleState. Released snapshots are immutable. Demonstration amendment means a new revision of an unreleased record; a post-release change must be a new linked draft needing all approvals. Cancellation/expiry/supersession are separate explicit states, never inferred from deletion or clocks. Do not expose operational cancellation or implement UPDATE/CORRECT/CASCOR semantics without approved rules; these remain deferred under UC8-1. Test released mutation denial and relationship integrity, document the unsupported commands visibly if offered.

## Notional state/permission model

Originator saves Draft and submits to Division Officer. Division Officer -> Department Head -> CHENG -> XO -> CO is the fixed demonstration route, with no skipping or delegation. Only the current reviewer can comment, approve/forward or return; originator can comment on its own draft, save and submit. Each reviewer except CO approves and forwards; CO records final approval with Simulate release. Return requires nonempty reason and returns to Originator. Resubmission always begins at Division Officer. Editing a committed unreleased report as Originator, including while under review, makes a new Draft and invalidates all current approvals. No-op saves create no revision. Released content cannot be edited in place. Conflicts block submission, review and release until explicitly resolved; resolution restarts Draft with no approvals.

Changing persona alone grants no real authority; enforce the above simulated permissions in core as well as UI. A release attempt before complete current-revision review must show the frozen error without changing holder/history/approval state. Wrong-role attempts similarly fail. #release stays clickable to explain rejection in the acceptance journeys. Valid decisions require a clean draft buffer. Do not silently approve the saved snapshot while the user sees unsaved text.

## UX and selector contract

ux-spec.json is authoritative for screens, states, keyboard and persistence. acceptance-plan.json contains literal independent expectations and stable selectors; implement each exactly. #persona values are originator, division, department, cheng, xo, co. #equipment and #casualty edit a local draft; #save-draft commits; #discard-changes explicitly restores saved text; #submit, #review-comment, #return, #approve-forward and #release drive review. Narrow result nodes #save-status, #workflow-status, #approval-status, #validation-error and #action-error contain only their planned message.

History nodes #history-original and #history-return expose the first saved casualty and first return reason; full history also includes all events. #open-amendments reveals a secondary Synthetic competing-edit simulation panel. #amendment-a/#amendment-b are two edits anchored to the current saved base; #stage-amendments creates both immutable branches together. This is a real application DAG operation with synthetic input, not a static fixture output. #conflict-a/#conflict-b/#conflict-base show both competing values and lineage. #resolution is user-edited chosen content; #resolve creates a new revision with both heads. #history-amendment-a/#history-amendment-b retain originals after resolution. #resolution-parents is a readable confirmation; the core test independently checks actual parent IDs. #export downloads synthetic-casrep.txt only after simulated release, including approved content, all revision snapshots, comments, decisions, actor/role/revision/digest/time and synthetic notices.

Fresh contexts isolate each journey. Reload within a journey must preserve its committed content, draft, conflicts, decisions and release. Exact planned expected text is in JSON; it was chosen before any implementation output. These expectations prevent drift, but are not independent SME ground truth.

## Failure and recovery requirements

Validate empty/whitespace and length boundaries before persistence. Keep all draft content on validation/permission failure. Handle quota/security errors with no Saved claim and no approval advance. Corrupt or unknown-version storage must offer a clear error and readable recovery without overwriting existing bytes. Use generation checks to reject stale write attempts; retain local draft and both competing snapshots for explicit resolution. A failed reconciliation preserves original history and pending input, identifying missing parents rather than dropping records. Never choose heads by timestamp. Escaping must make synthetic markup render as text in UI/export. No test-only buttons are needed for storage failures; inject adapter failures into core tests.
