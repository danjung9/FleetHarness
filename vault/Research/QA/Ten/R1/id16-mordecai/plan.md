## Scope and traceability

Build a dependency-free offline oversight console: eligibility → intent announcement → simultaneous batch arbitration → exclusive resource lease → deliberate simulated execution → enforced operator halt. Audience is an evaluator acting as an operator. Success is an explained decision with no unauthorized simulated action and a halt that survives reload. The only execution is a local counter and action report; there are no agents, actuators, network calls or operational endpoints.

## Synthetic domain contract

State schemaVersion 1: sessionId, now (integer seconds), revision, halted boolean, condition, policy, agents[], authorizationLeases[], resourceLeases[], intents[], decisions[], actionReports[], haltAcknowledgements[], audit[], drafts. All commits produce a new revision and append readable audit records. A validated restored state must satisfy all reference and ownership invariants before controls enable.

Default now=100; no wall-clock timer. pump-1 is an exclusive invented resource with allowed action inspect. Agents sensor (class sensing, base 60) and repair (class repair, base 40) begin with manifest validity [0,1000), authorization validity [0,200), heartbeatAt=100, and all four declared contract flags heartbeat/intent/actionReport/halt=true. Default intent selects repair. IDs are unique ASCII letters/digits/hyphens; bounded nonempty display names render as text. Ghost is initially absent. Its repair registration creates class repair, base 20 and the same valid intervals/flags. No signature or verified-identity badge.

Manifest: id, displayName, class, allowedActions, validFrom, expiresAt, contract flags, heartbeatAt. Authorization lease: id, agentId, resourceId, action, validFrom, expiresAt; separate from awarded resource ownership. Lease validity is validFrom <= now < expiresAt; now equal expiry is expired. Heartbeat is fresh when 0 <= now-heartbeatAt <= 10. Future, nonfinite, fractional or malformed times fail closed. Eligibility checks halt first, then structural validity/references, registration, manifest interval/contract/action, authorization lease, heartbeat. Malformed telemetry cannot cause a grant. Liveness is not identity assurance.

Policy data demo-v1: higher score wins; score=baseRank+conditionModifier[class]+promotion[agent]. Cruising modifiers are zero; general-quarters gives repair +30 and sensing +0. Repair promotion is an integer 0 to 100, initially 0, saved explicitly by the local operator. Promotions never bypass eligibility, resource exclusivity or halt. Exact top-score ties escalate with no winner; do not use arrival or ID as authority. Sort roster by descending score, then ID only for presentation of ties. Retain policy version and full evaluated values per decision. The immutable demo-v1 rules plus committed condition/promotion input snapshot identify each decision.

Intent: unique id, batchId, agentId, resourceId, action, announcedAt, status. Statuses include pending, rejected, granted, denied, canceled, completed; rejection has a reason. An intent must be announced before resolving and never directly executes. Queue competing requests creates sensor and repair requests in one explicit batch at t=100, with arrival order selectable; allocation IDs may differ but the winner must not. Duplicate ID is rejected and cannot double-allocate or double-execute. Do not mutate an already executed receipt.

Resolve: inspect the entire open batch at one now/revision; recheck all contenders, calculate scores only for eligible agents, and grant at most one exclusive resource lease per resource. Lease: id, holder, intentId, batchId, issuedAt, expiresAt=now+5, status. Any existing unexpired ownership blocks conflicting allocation; re-resolution releases only that batch's unexecuted grant before calculating again. Ties keep the contenders available for deliberate re-resolution. Other losers remain visible with scores/reasons. A one-contender valid batch may win without a comparison sentence. No resolve step executes an action.

Decision receipt: decisionId, session/revision/time, batchId, policyVersion, condition, complete candidate score/eligibility input snapshots, winner/null, reason, leaseId/null. Condition or promotion commit invalidates unexecuted grants and marks decision obsolete; operator must Resolve again. Revalidate revision, heartbeat, manifest, authorization and current ownership at Execute. If anything changed or expired, refuse action. Action report: actionId, decisionId, intentId, agentId, resourceId, action, time and completed result. Execute is idempotent, consumes one grant and releases ownership on completion. Already completed work is never retroactively canceled.

Halt is a reducer-level guard on announcement, allocation, eligibility repair and execution, not a UI label. It atomically sets halted, cancels all pending/granted intents, revokes active leases and appends one simulated acknowledgement for every registered agent (sorted by ID). Historical actions remain. Execute and submit stay usable while halted to show explicit blocked reasons; other mutating controls are unavailable with an explanation. Repeated halt is idempotent. No resume in this slice. A separate confirmed New session discards this local session into an explicitly new one, never resumes its queued work. Normal scenario controls, reload and errors cannot clear halt.

## UX control and persistence contract

Use the exact selectors and text in acceptance-plan.json. Single-page console sections must be usable at desktop/narrow widths. Native labeled controls, visible focus, text-based status and task language are required. Keep synthetic boundary and Halt all simulated agents prominent; scenario controls and raw snapshots are secondary. All result selectors target one narrow element, not a parent containing unrelated text.

Controls: #agent-select, #submit-intent (Announce intent), #queue-contenders (Queue competing requests), #arrival-order (sensor-first default or repair-first), #resolve (Resolve batch), #execute (Execute approved action), #clear-batch (Clear batch), #halt, #condition and #apply-condition, #promotion and #save-promotion. #discard-promotion and a condition discard action recover unsaved edits. Unsaved policy inputs cannot silently replace committed policy or approve a decision under different values; require save/discard first.

Secondary scenarios: #eligibility-case values missing/expired/stale; #load-case establishes t=100, repair defaults and one selected case, cancels unexecuted batch state but preserves audit/completed actions. Missing selects ghost with no manifest; expired selects repair and authorization expiresAt=100; stale selects repair heartbeatAt=89. Each case leaves other eligibility fields valid. #repair-eligibility registers ghost or restores repair expiry=200 and heartbeat=100, shows the correction, cancels no historical rejection and never resubmits automatically. Controls cannot change halted state. Fresh default context has two registered agents, no pending work, executed count 0. Scenario loading is a deliberate synthetic exercise control, not a hidden operational fault injection.

#clear-batch cancels unexecuted work/releases the current grant, clears the decision display and preserves completed history, policy, clock and halt. It does not enqueue a new batch or clear deduplication history. New batches use fresh intent IDs. #pending-count counts only unresolved pending intents; queue on a fresh batch shows 2; halt shows 0. #executed-count is completed report count. #action-latest contains only the report sentence. #halt-acks contains sorted agent acknowledgement text. #roster-order is a compact human-readable score summary, alongside the full roster. Empty latest action/decision is None.

Persist validated committed state to a versioned localStorage key and restore at startup, including halted state. Also preserve draft policy edits, clearly distinct from committed values. Storage failure keeps memory state and visibly reports Session not saved; export remains available. JSON export contains synthetic state/audit only. Corrupt restore fails closed with an explicit discard/new-session recovery, never silently enables actions from partial data. Human review must assess file URL storage compatibility across intended browsers; host reload behavior is required. Reset is separate and confirmed; no journey depends on reset. Every host journey begins in a fresh context.

## Risks and review boundaries

No owner-approved ranks, heartbeat interval, lease duration, condition weights or promotion limits exist; above numbers are independently planned demonstration values. They are protected from implementation drift, not SME ground truth. Domain owners must review authority precedence, escalation, expiry, reset authority, stop acknowledgements and unsafe/in-flight work semantics before any new operational design. Cryptographic key lifecycle, agent adapters, reliable time, distributed contention, access controls, tamper-evident audit, retention and production policy enforcement need separately validated infrastructure. Local storage can be changed by a user and is not trusted evidence. Browser checks prove only specified interactions; human review retains GOV-03's original method and assesses clarity, keyboard use and simulation boundaries. No claim of runnable, tested, reviewer-accepted or operationally validated status is made during planning.
