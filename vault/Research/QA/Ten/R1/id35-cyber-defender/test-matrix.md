## Risks and operational requirements needing human review

The baseline and answer key are authored in this separate planning phase to prevent implementation drift; they are not independent SME ground truth or approved STIG content. Owners must validate applicability, asset classes, control releases, mission impacts and a representative corpus before using any result for decisions. Inspect the same fixed manual scenario for handoff completeness, time and effort; no baseline or savings threshold is supplied. Clarify audit coverage/retention/integrity and authenticated reviewer roles. Browser storage is mutable, local and may be unavailable for file URLs. JSON export is not synchronization or an agreed integration.

An explicitly authorized isolated lab and reviewed adapter/tests must cover stale-approval execution rejection, successful and failed rollback, partial remediation, verification failure, and complete audit reconciliation before any execution claim. Supply a constrained-link emulator with payload, bandwidth, latency, loss and pass thresholds. Independently review actionability with commanders, system owners and data owners. Actual judging retains Warfighting 30%; Speed to Fleet 20%; Scalability 20%; Barrier Removal 15%; Judges' Discretion 15%. No score is generated.

Generated planning artifacts are distinct from runnable software, tested software, reviewer acceptance and operational validation. Build verification.md later with actual results, skipped checks and limits; do not edit frozen JSON, .fleet/ or host evidence. One bounded implementation repair may address failed gates without weakening expectations.
