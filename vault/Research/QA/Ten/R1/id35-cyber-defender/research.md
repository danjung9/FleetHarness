## Options and unresolved integration questions for planning

The strongest supported option is a self-contained synthetic evidence/proposal demonstration with explicit control revisions and portable citations. Another conditional option is a policy engine backed by a pinned, locally distributable release and independently reviewed synthetic rules, once license and runtime evidence exists. A future scanner-output import is a different option from live scanning and needs a documented synthetic export contract. None of these options expands the present authority boundary.

The main integration risks are:

- **Applicability and false certainty:** missing asset attributes, unsupported control versions and ambiguous logs must stay uncertain. The seeded issue and benign look-alike require independent expected answers; unknown fields must not imply compliance or a confirmed finding. No official severity or mission-impact rule is supplied.
- **Review validity:** approval must bind the exact affected assets, before/after content, prerequisites and relevant reference revisions. A mutable proposal identifier is insufficient. Canonical digest input, version coverage, rejection and stale-review semantics remain unresolved. Review cannot be reused as execution permission.
- **Handoff and audit loss:** exports need source IDs, revision/timestamps, exact evidence locations, proposal review history and unexecuted statuses. Local event records can be changed or lost; persistence, ordering, retention and integrity rules remain unspecified. No operational audit assurance is inferred.
- **Offline packaging and transport:** no supported browser, installation model, storage limit, evidence size budget or emulated link profile is given. Local-only operation cannot prove low-bandwidth transfer, reconnection, conflict resolution or fleet scalability.
- **Execution and rollback:** before any future lab integration, an authorized adapter and reviewed tests must cover stale approval rejection, failed rollback and partial remediation. Neither proposal text nor a toolkit fixture can establish these outcomes. Current outputs must remain “not executed / not verified.”
- **Supply chain and distribution:** both external candidates need version-pinned primary documentation, license text, dependency/content inventory and platform evidence. Local toolkit rights are also unspecified. No compatibility, deployment or redistribution conclusion is established.

Owner/domain questions remain: Which synthetic asset types and control applicability rules are approved? Who supplies the independent seeded/benign answer key and correctness rubric? Which exact bytes and revisions define the review scope? Which external import/export schema must interoperate? What browser, evidence limits, retention rules, bandwidth/latency/loss settings and pass thresholds apply? Who can independently assess commander/system-owner/data-owner actionability? What fixed manual scenario establishes timing and analyst-effort baselines? These questions bound confidence; research does not invent their answers.
