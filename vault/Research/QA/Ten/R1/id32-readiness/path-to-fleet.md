# Path to fleet, owner handoff

This is a synthetic, offline dependency-timing prototype. It has no operational connections and is not a validated mission-readiness model. No response or command decision is automated.

**Ownership:** Naval Surface Forces / Task Force Hopper is the challenge's proposed sponsor and destination, not a confirmed sponsor or approved endpoint. Operational sponsor, model approval authority, data steward, security lead and sustainment owner are unresolved. An owner must accept responsibility before field validation.

**Users, devices and hosting:** Intended users are analysts and leadership reviewers. Current route is a self-contained index.html opened on a desktop browser; no installation or server is required. Approved government device, browser, hosting route, accessibility standard and offline storage permissions are unresolved. A future offline package needs owner-controlled versioning, integrity/signature checks, distribution, migration, backup and retention policy. Keep an approved previous package and exported synthetic briefs for rollback; present local storage has no migration guarantee. Government-device installation is not approved by this package.

**Data and integration boundary:** Synthetic only; no operational classification or handling approval is inferred. No ingestion, source writeback, CAC, transport, source sync or reconnect sync exists. Representative 8 O'Clock/1200, maintenance, casualty, parts, qualifications and schedule feeds require approved schemas, stable asset IDs, record revisions, observed/sync times, conflict rules, authentication and access authority. Operational retention, encryption and audit assurance need independent implementation and review. Source records in this prototype are immutable bundled examples; local what-if edits remain local.

**Evidence:** Application Node tests exercise both core.cjs and the embedded HTML core, including negative/boundary cases. See verification.md. Host browser journeys, human usability review, security assessment, external integration and operational evaluation remain pending. The local calculation tool only cross-checks supplied arithmetic. There is no SME-reviewed scenario, validated capability model, approved risk priority policy, false-alarm corpus or manual time baseline. Toolkit adaptation has no declared upstream license/version; research.md records supplied source hashes. No external packages are used; reuse clearance remains unresolved.

**Concrete next validation:** Proposed sponsor must name an operational model owner. That owner and a Fleet SME should review every dependency, elapsed-day convention, concurrency and resource assumption, personnel-to-availability mapping, freshness rule, all five synthetic changes and an independent answer key. Success means a signed model/scenario baseline and documented agreement or corrections for all target finishes, uncertainty and consideration order. Then an analyst/reviewer should complete the frozen desktop/narrow journeys and assess evidence clarity and recovery with no stale exports. Security and data owners must authorize representative data before any operational ingestion work.

The challenge's 30/60/90/180-day transition hypothesis is owner model validation / representative-data access / shore pilot / integration decision. These are proposed milestones, not commitments or achieved approvals. Future sustainment owner must set success measures for noise/rank accuracy, manual assembly-time comparison, offline durability, controlled sync and rollback before a one-ship shore pilot. No local pass establishes authority to operate or mission capability.
