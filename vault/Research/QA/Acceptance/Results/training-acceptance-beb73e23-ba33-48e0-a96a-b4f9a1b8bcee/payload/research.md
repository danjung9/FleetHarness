## Integration risks and concrete options for planning

The supplied helper is a small feasibility option; OR-Tools is an unverified larger-scale alternative; the scope also permits a clearly labeled conflict-checker fallback with person-selected times and independent checks if automatic generation is not accepted. A fallback cannot claim automatic generation or erase unmet criteria. This research does not choose a UI, storage architecture or implementation sequence.

Important semantic boundaries from inspected source:

- Qualifications are covered collectively by the exact assigned people; resources are exclusive identifiers, with no capacity configuration. These fit the one-person/one-room synthetic requests but do not define broader qualification authority or resource policy.
- Rest is checked against every assigned interval for a person, not only search-order neighbors. Zero rest permits touching half-open intervals; a 30-minute gap must remain explicit. Budgets cover the entire supplied horizon, not each day.
- The helper accepts at most 200 people, 24 requests, 100 starts per request and 100 windows per window array. Default maxNodes is 50,000, allowed range 1 to 200,000. These are implementation bounds, not performance evidence. Search order and a node limit can affect exhaustion; observed conflict messages are not a minimal explanation or proof that a particular constraint alone is responsible.
- Nonfeasible outputs contain an empty assignments list. The editable requests must remain available independently. Otherwise an ordinary helper response could appear to drop sessions. Review invalidation, personnel totals, import error recovery and preservation of exact inputs/draft are application responsibilities.
- Successful static analysis establishes neither browser packaging nor save/import recovery. Remote imports/assets would conflict with self-contained offline delivery. Browser file handling and exact round-trip behavior remain untested.

Outstanding questions for later planning are the portable file schema, malformed/oversized/foreign import behavior, preservation versus revalidation of imported drafts, review restoration semantics, evaluator access to exhaustion cases, and supported local-file browser behavior. Owner questions for any future expansion are authoritative fatigue/budget windows, qualification policy, recurrence/deadline/SFTRM rules, negotiation authority, optimization objectives and approved interfaces. None blocks the explicitly supplied synthetic arithmetic, and none is answered by choosing a solver.
