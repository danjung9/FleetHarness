# v0

## Bottom line

[R] Use v0 as a reference for quickly turning a concrete workflow into a reviewable interface. [V] Current documentation covers full-stack apps, not just isolated UI components (https://v0.app/docs/full-stack-apps). [R] Borrow its source-control handoff and targeted design iteration. [R] Keep mission rules and disconnected tests outside visual approval.

## The first ten minutes

[E] Documentation-based proposed walkthrough, read November 4, 2026; no live build was timed. [A] Account, sandbox and generation delays can exceed ten minutes.

1. [R] Minute 0 to 1: personally sign in at https://v0.app. Start a new chat with synthetic data only.
2. [R] Minute 1 to 3: apply the Plan Mode instruction through the prompt's plus menu. Request a fictional training request dashboard, a conflict list and one reviewer approval action. Require no external writes.
3. [R] Minute 3 to 4: review its proposed screens, data fields and assumptions. Specify that overlapping room bookings must fail.
4. [R] Minute 4 to 7: approve generation. Inspect the preview at desktop and narrow mobile widths.
5. [R] Minute 7 to 9: enter the overlap and valid-booking examples. Use Design mode for a small layout adjustment. Record any action that only changes local UI state.
6. [R] Minute 9 to 10: ask which features use mock data and which call a server. Save the version and identify the export path. Do not deploy.

[V] The documented Plan Mode preset requests a detailed approach and approval before implementation. It is an instruction preset; the cited page does not establish an external enforcement boundary (https://v0.app/docs/instructions).

## How it decides and asks

[V] v0 defaults to Next.js and can add server endpoints, data persistence and third-party integrations. It can prompt the user to create a needed resource. Its guide recommends incremental UI, data and authentication work (https://v0.app/docs/full-stack-apps). [A] A mandatory domain-requirements interview was not verified. [R] Ask it to expose its assumptions before it chooses the schema.

## Checking the result and real-app limits

[V] The FAQ describes a full-app sandbox preview and an optional GitHub flow with branches, automatic commits and pull requests (https://v0.app/docs/faqs). [R] Use the preview for usability and separate tests for permissions, constraints and persistence. A production-like runtime does not make a test representative of production traffic or identity.

[R] The likely handoff points are database migrations, identity federation, transactions and synchronization. A simple CRUD dashboard cannot establish correctness of a constraint solver. Keep expected outputs in a versioned acceptance file and rerun them after each accepted change.

## Data, login and security evidence

[V] The full-stack guide supports integrations such as Supabase, Neon and Upstash, and describes project environment variables. Variables exposed to browser code use the NEXT_PUBLIC_ prefix (https://v0.app/docs/full-stack-apps). [R] Never place a secret in a browser-exposed variable. Require server-side authorization in addition to a sign-in screen. [A] The selected identity provider and retention terms were not verified.

[V] Platform dependency incident: Vercel's April 2026 bulletin reports unauthorized internal access originating through a compromised third-party AI tool, with a subset of customers' environment variables compromised. The bulletin recommends credential rotation and stronger environment-variable handling. This is hosting-platform evidence, not proof of a defect in v0-generated code (https://vercel.com/kb/bulletin/vercel-april-2026-security-incident).

[V] Independent preliminary study: nine generated apps, three per tool, were statically analyzed. It reported different structural issue profiles for v0, Lovable and Replit. The sample is too narrow to rank current production safety (https://arxiv.org/abs/2608.16302). [A] No directly verified v0-specific generated-app exploit was established in this pass.

## Export, offline and pricing signal

[V] The FAQ says source can be exported and deployed elsewhere; the v0 builder requires internet (https://v0.app/docs/faqs). [R] Treat offline operation as work on the exported application's storage, identity and dependencies. Demonstrate opening, editing, restart and resynchronization without the hosted builder.

[V] The pricing documentation lists Free, a $30 per user monthly Team tier, $100 Business and custom Enterprise. It says the older $20 Premium plan is being sunsetted for new users; included credits and additional purchases affect generation costs. Business has a data opt-out and Enterprise adds SAML SSO (https://v0.app/docs/pricing). [A] Plan naming differs across current pages, including Plus versus Team; confirm checkout. [R] Budget hosting and database usage separately from generation.
