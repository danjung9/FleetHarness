A training coordinator edits four supplied synthetic requests, generates a feasible draft over explicit starts, reads each assignment and whole-horizon personnel load, corrects errors, deliberately reviews the current checked draft, and saves/imports exact inputs and draft offline. A complete failure result retains all four editable requests. This is a two-day administrative practice example, not an issued schedule.

The source's departmental agents, negotiation and SFTRM compliance (UC11-1), mandatory periodicity (SCH-04), and weekly optimization/heatmap deliverable (DELIVERABLE11-1) remain deferred in full. ## Inputs and domain contract

Epoch is `Day 1 minute 0`; day two begins at 1440. Intervals are half-open, integer minutes. Both operating and personnel windows initially equal [[0,240],[1440,1680]]. P01 has Q-A, maxMinutes 120 for the entire two-day horizon and minRestMinutes 30. P02 has Q-B, maxMinutes 120 and minRestMinutes 0.

| Request | Duration | Candidate starts | Fixed person | Fixed room | Required qualification |
| --- | --- | --- | --- | --- | --- |
| A | 60 | 0 | P01 | Room-1 | Q-A |
| B | 60 | 0, 90 | P01 | Room-1 | Q-A |
| C | 60 | 0 | P02 | Room-2 | Q-B |
| D | 60 | 1440 | P02 | Room-2 | Q-B |

Keep exactly A to D and P01/P02 in this slice. Request identities, person/room assignments and required qualification are fixed, readable labels. Editable fields include duration, starts, supplied person qualifications, person availability, budget/rest, operating windows and advanced maxNodes. An explicit qualification edit changes the synthetic problem and invalidates review; the solver must never invent one. Qualification policy beyond literal membership is excluded. Default maxNodes is 50000; valid range 1 to 200000. Start lists are comma-separated integer minute values; window lists use `0-240;1440-1680`; qualifications use comma-separated nonempty tokens. Missing qualification membership is a feasible-search constraint failure, not malformed syntax.

Use safe nonnegative integer starts and window boundaries; positive duration, nonnegative rest and budgets, nonempty candidate lists/windows, strictly increasing window endpoints. Limit lists to 100 entries, tokens to 80 characters and portable files/text to 1 MiB UTF-8. Reject malformed or unknown identities, duplicate fixed entities and nonfinite/unsafe arithmetic. Preserve original structured values and candidate order in saved inputs. Search may use a separate normalized copy but must not mutate inputs or canonicalize saved candidate lists. Preserve raw invalid field text in the editor instead of coercing blank to zero.

## Calculation and result contract

For each candidate, require entire [start,end) containment in an operating window and assigned-person availability window, literal qualification coverage, no person overlap, rest at least the person's supplied minimum between every interval pair, no shared-room overlap and summed assigned duration at most maxMinutes across the whole horizon. Zero rest permits touching intervals; positive rest does not. Fixed assignments are never selected or reassigned by the solver. Search choices are only listed start times.

Traverse requests A, B, C, D and unique candidate starts in ascending order deterministically. Count each attempted candidate against maxNodes; if another candidate is needed after budget is consumed, return exhausted, not infeasible. Budget 1 cannot complete the four-request baseline. Return infeasible only after fully exhausting the supplied combinations within budget. A valid solution at the final permitted attempt remains feasible. Cancellation, if added, is unknown rather than proof of infeasibility. Never show partial assignments as a complete feasible result.

Core outcome variants: feasible with complete assignments and loads; infeasible with observed conflict reasons; invalid with field errors; budget_exhausted with unknown feasibility. Only feasible results have current assignment cards and computed scheduled totals. Nonfeasible results keep all input rows and suppress obsolete current results. Plain-language UI strings, exact result-card text and narrow selectors are frozen in acceptance-plan.json. Observed diagnostics are not a minimal unsatisfiable core.

Run checkDraft independently before rendering success or enabling review: validate complete unique request set, permitted starts, exact duration/end arithmetic and fixed assignments, all pair constraints, window containment, qualifications and whole-horizon totals. Recompute loads from assignments, never imported summary totals. A failed independent check blocks success and preserves inputs. Node tests must use an independent pairwise oracle rather than asserting the solver's own status flag alone.

Independent baseline expectation is A [0,60), B [90,150), C [0,60), D [1440,1500), P01/P02 each 120. D duration 30 means D [1440,1470), P02 90. These values are arithmetic planning expectations, not an application verification result. No model is required; explanations are deterministic templates grounded in checked constraints. Any future model-assisted explanation must remain separate from calculation and cannot relax a constraint, fabricate a rule or claim SFTRM interpretation.

## Portable persistence and replacement boundary

Snapshot schema is an application data contract, distinct from the host's quality JSON formats. Use exactly `{schemaVersion:1, classification:"synthetic", inputs, draft}`. `inputs` has epoch, operatingWindows, people, requests and maxNodes. Person fields are id, qualifications, availability, maxMinutes, minRestMinutes. Request fields are id, duration, starts, person, room, qualification. `draft` has status, assignments and loads; each assignment has requestId, start, end, person and room. The portable journey contains an entire literal valid example. Status values use the core variants; invalid unsolved raw text is retained locally as unfinished work rather than represented as a trusted valid snapshot. Save of a valid problem may include infeasible/exhausted draft with empty assignments and loads; review stays unavailable. Canonical compact JSON output permits the frozen download substrings, including `"classification":"synthetic"` and `"end":1470`.

`#save-portable` deliberately saves exact current structured inputs and draft to local storage and downloads synthetic-training-draft.json. Show success only for storage+download initiation; if storage fails, clearly report that only portable recovery is available. Save/reload restores checked exact inputs/draft, but not trusted review. Separately preserve unfinished raw edits on ordinary interactions when local storage is available; do not silently overwrite the explicit saved checkpoint. Clear saved/unsaved labels must distinguish these states. No dependency on clipboard permission or a filesystem handle API.

Support file import and accessible `#import-text` textarea using the same parser/validator. `#stage-import` parses without replacing work, validates version/classification/size/fixed identities and independently checks the draft against its inputs. Reject mismatched totals, assignments or feasibility claims; for nonfeasible statuses rerun search using saved budget to establish the claimed status. Import does not prove review. The preview shows current and incoming values for changed requests/rules, draft and totals. `#confirm-import` is labeled Replace current work and deliberately discards the current unsaved editor in favor of the staged input; offer Save current work and `#cancel-import`. Changing the staging text invalidates the preview so confirmation cannot apply a different payload. Invalid import/cancel leaves current problem/result/review unchanged. Confirmed import resets review and marks the new snapshot unsaved until explicit save. No merge or sync is implied.

The portable journey downloads a D=30 snapshot, reloads, changes D to 45, imports the independent literal D=30 snapshot, confirms replacement, and checks D/P02 values and export again. Node tests must additionally serialize actual current data and parse that exact string for deep equality, including order, every input and complete draft; literal import alone is insufficient evidence of arbitrary round-trip. Manually reopen the actual index.html offline and import the downloaded file to cover the runner's absent upload action. Manual absence must be recorded as unverified, never assumed passed.
