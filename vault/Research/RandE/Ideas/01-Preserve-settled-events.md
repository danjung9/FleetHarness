# Preserve settled events

## Bottom line

[R] Offer Keep this time on an event in a previously reviewed draft. [R] After an edit, preserve locked placements and prefer the feasible result that moves the fewest other events. [A] Avoiding unnecessary changes could matter more to a coordinator than producing another valid calendar.

- **Moment [R]:** Change one fictional request; show exactly which other placements must move. If locks prevent a solution, report that and leave them intact.
- **Novel increment [E/A]:** Existing notes propose before/after review and preferences. This adds explicit placement locks and a measured count of moved events; no equivalent recommendation was located in the scan.
- **Judge evidence [R]:** Use a four-event case with several feasible answers. Independently enumerate it to check the fewest-moves claim. Any new draft still needs review.
- **Size [A]:** 2 to 4 person-hours for the bounded app, including the check. Restrict the objective to changed start times; define a deterministic tie rule.
- **Verdict [R]:** Keep only after core acceptance. Kill if it needs a general optimizer, breaks a hard constraint, or users do not value stability. A valid solution alone does not prove fewest changes.
