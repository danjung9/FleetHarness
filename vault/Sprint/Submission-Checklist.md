# Submission checklist

Built from [[Event/Rules]] and [[Event/Terms]] [P]. The portal's actual submission form was not seen, so check its fields as soon as we have a team.

## The problem

- [ ] User named (rule 2)
- [ ] Operational problem stated (rule 2)
- [ ] Current process described (rule 2)
- [ ] Burden reduced, with a measure (rule 2)
- [ ] Challenge category chosen
- [ ] OSW ROI named, with evidence (rule 1)

## The build

- [ ] Observable prototype, test, workflow, integration or technical finding (rule 3)
- [ ] Only unclassified data, with no CUI, PII or nonpublic government data (rule 4)
- [ ] Fleet conditions addressed: cybersecurity, portability, limited connectivity, shipboard limits, sustainment, disconnected use (rule 9)

## Human authority (rule 6, and category 1 if we enter it)

- [ ] What the system may do
- [ ] What it must never do
- [ ] Human approval points
- [ ] Logging and monitoring
- [ ] Escalation
- [ ] Shutdown procedure

## Disclosure

- [ ] Tools, models, datasets and external services listed (rule 5): [[Sprint/Tool-Disclosure-Log]]
- [ ] Pre-event work separated from event work (rule 7, terms sections 5 to 7): [[Sprint/Prior-Work-Log]]
- [ ] Contribution ownership and restrictions documented (terms section 7, if non-government)
- [ ] Friction documented: policy, data, authority, infrastructure, acquisition, technical (rule 10): [[Sprint/Friction-Log]]

## Beyond Friday (rule 11)

- [ ] Mission owner
- [ ] Technical owner
- [ ] Next experiment
- [ ] Required resources
- [ ] 30-day recommendation
- [ ] 60-day recommendation
- [ ] 90-day recommendation

## Pitch against the rubric

- [ ] Impact number up front (30%)
- [ ] Path to disconnected fielding (20%)
- [ ] Reach across classes, ratings or domains (20%)
- [ ] Bottleneck removed (15%)
- [ ] Clean technical demo and Sailor experience (15%)
- [ ] Mission results rather than vendor positioning (rule 8)
